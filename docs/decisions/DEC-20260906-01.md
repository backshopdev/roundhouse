# DEC-20260906-01: Commit messages flow through a Node-based commit script

Status: Active
Last modified: 2026-09-06
Date: 2026-09-06
Context owner: (workflow harness repo)

## Context

Twice in PLAN-20260904-02 execution (commit 9915a9c and an earlier
renamed-commit path), PowerShell-based commit-message writing corrupted
non-ASCII characters — specifically the em-dash (U+2014, UTF-8
`E2 80 94`) was re-encoded to `CE 93 C3 87 C3 B6` (the classic
"UTF-8 bytes read as Latin-1 then re-encoded as UTF-8" pattern).
The workaround in both cases was to use a .NET-based byte-exact write
(`[System.IO.File]::WriteAllText` with `[System.Text.UTF8Encoding]::new($true)`,
or explicit byte arrays).

This isn't just a correctness problem — it's a token-cost problem.
When the message file is corrupted, the orchestrator must detect the
problem (often after commit), amend with a corrected message, and
re-push. That's an avoidable ~5-minute loop per occurrence, plus the
diagnostic tokens. Given the commit convention mandates multi-line
bodies, every commit is potentially exposed.

A byte-exactness experiment (v24.20.0 / Windows, three approaches:
default string write, `Buffer.from(str, 'utf8')`, explicit
`encoding: 'utf8'`) confirmed that **Node's `fs.writeFileSync` is
byte-clean for all three invocations** on the supported runtime.
No encoding footgun exists in Node — the corruption is
PowerShell-specific. So a Node-based fix is both correct and
low-cost: the runtime is already a hard dependency
(`engines.node >= 24.0.0`), and the script would be cross-platform.

## Decision

**All agentic commit messages must be written through a Node-based
script** (`scripts/commit`, project-local; later shipped to consumers
via the npm package). We are prescribing this method because we
know it works and to conserve tokens. The script will:

- Use `Buffer.from(message, 'utf8')` then `fs.writeFileSync(path, buffer)`
  to guarantee byte-exact UTF-8 writing (the canonical Approach B
  from the experiment).
- Accept subject and body via CLI flags (not stdin, not positional).
- For long bodies, accept a `--body-file <path>` option so the body
  can be authored in a file and passed verbatim.
- Call `git commit -F <message-path>` with the byte-exact message file.

The git-commit skill will be updated to mandate use of this script for
agentic commits. The commit-convention skill does not need to change
because it documents format, not execution.

Humans writing commit messages directly (e.g., in their editor of
choice) are not affected by this decision — they are not in the
agentic loop and have direct control over what gets committed.

## Alternatives considered

| Option | Aligns with our needs | Cost | Notes |
|--------|----------------------|------|-------|
| **Use Node script with Buffer.from + writeFileSync** (chosen) | yes | one-time script development | byte-clean, cross-platform, runs in CI without extra setup |
| Continue using PowerShell with .NET workarounds | partial | ongoing tokens on every non-ASCII commit | human review gate catches corruption, but at real recurring cost |
| Add a Git hook that validates message bytes pre-commit | partial | hook development and maintenance | defense-in-depth, but doesn't fix the root cause (the file was already corrupted before git saw it) |
| Switch to a different shell entirely (e.g., bash, zsh) | yes | tooling change, doesn't help on Windows | bash on Windows has its own encoding quirks; cross-platform is a wash |
| Document the .NET workaround as the standard | no | ongoing tokens, non-portable | locks the standard into a PowerShell-only path |

## Consequences

- (+) Commit message corruption is eliminated at the source — no more
  em-dash / arrow / smart-quote damage from agentic commits.
- (+) Cross-platform: the same Node script works on Windows, macOS, Linux.
- (+) Already a Node dependency (`engines.node >= 24.0.0`), no new tooling.
- (+) Token cost: no more amend-and-repush loops for corrupted messages.
- (-) One-time cost: build and maintain `scripts/commit` (and ship it
  to consumers via the npm package later).
- (-) Git-commit skill must be updated; downstream agents that don't
  load the updated skill may still try unsafe paths.
- (-) The script must handle edge cases (missing args, empty body, git
  failures, etc.) — non-trivial but well-bounded.

## Exit criteria

- `scripts/commit` exists, is documented, and is the documented
  commit-message path in the git-commit skill for agentic use.
- The git-commit skill mandates use of `scripts/commit` for any
  agentic commit (with non-ASCII content explicitly, and as a general
  best practice).
- A test exists that verifies `scripts/commit` produces byte-clean
  output for representative inputs (em-dash, arrow, smart quotes,
  non-ASCII names).
- The npm package (future work) ships `scripts/commit` so consumers
  get the same guarantee.
