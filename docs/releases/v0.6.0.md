# Release v0.6.0

## Summary

Minor release introducing a generalist Implementor agent for
executable software changes, a reusable `investigation` skill that
replaces the dedicated Investigator agent, and a `test-enablement`
skill specializing `design-for-testability` for legacy-code
enablement. The minimum supported Node runtime advances from 22 to
24. No planned breaking changes for existing prose-authoring
workflows, but consumers running custom Implementor-style work
should review the agent topology change.

## Changes since v0.5.1

- **`feat(agents)`**: added Implementor agent
  (`src/.opencode/agents/implementor.md`) for executable software
  changes. Owns file edits for code, configuration, and scripts
  under an 11-step lifecycle (Preflight → Classify → Test-first
  → Implement → Targeted verify → Repeat → Documentation sync →
  Final verify → Completion checklist → Packet). Codifies a
  standing quality posture covering testability, readability,
  documentation freshness, security, accessibility,
  maintainability, and no-quality-regression.
- **`feat(skills)`**: added `investigation` skill
  (`src/.opencode/skills/investigation/SKILL.md`) replacing the
  dedicated `investigator` agent. Read-only discipline is
  prose-only, compensated by self-discipline, peer review, and
  orchestrator gate discipline (see DEC-20260905-01 for the
  architecture context; the discipline enforcement model is
  documented in the skill's "Read-only discipline" section).
- **`feat(skills)`**: added `test-enablement` skill
  (`src/.opencode/skills/test-enablement/SKILL.md`) as a
  specialization over `design-for-testability` for legacy-code
  enablement. Codifies the preferred ordering: prefer ordinary
  modern testing techniques when possible; use Feathers-style
  legacy-code seams (characterization tests, dependency breaking,
  sprout and wrap) only when current structure blocks normal
  testing; escalate if broader restructuring would be required.
- **`feat(agents)`**: retired the dedicated Investigator agent.
  Investigation is now a skill loaded by whichever agent needs it
  (orchestrator during planning; document-author or implementor
  during execution). Routing for the new Implementor agent is
  added to the orchestrator's task allowlist in `opencode.json`.
- **`feat(workflow)`**: generalized the completion-packet envelope
  to 11 fields shared by `document-author` and `implementor`:
  summary, files-changed, verification, documentation, attention-
  flags, assumptions-open-questions, ktlo, discovery, completion-
  checklist, human-inspect, next.
- **`feat(harness)`**: codified Preflight as a shared lifecycle
  concept in the harness skill (validates assignment is understood,
  internally consistent, executable in intended order, supported by
  available context, within authority). Codified progressive
  specialization as a layering contract (a specialized skill
  builds on a base skill without restating base content); see the
  harness skill's "Progressive specialization" and "Skill
  architecture patterns" sections.
- **`feat(docs)`**: updated `AGENTS.md`, `AGENTIC_WORKFLOW.md`,
  `README.md`, and autonomy docs to reflect the four-agent
  topology (orchestrator, document-author, implementor, reviewer)
  and the investigation-skill-as-skill pattern.
- **`chore(repo)`**: renamed project from
  `@backshopdev/opencode-roundhouse` to `@backshopdev/roundhouse`
  (CLI command `roundhouse`, npm package
  `@backshopdev/roundhouse`). See commit history; the rationale
  was to avoid implying OpenCode endorsement or affiliation beyond
  what the harness actually provides.
- **`build(node)`**: advanced minimum supported Node runtime from
  22 to 24 (see DEC-20260905-01). CI is now pinned to Node 24
  explicitly in `.github/workflows/publish.yml`; `package.json`
  `engines.node` advertises `>= 24.0.0`. GitHub Actions began
  deprecating Node 20 on hosted runners as of 2025-09-19, so this
  change aligns the declared minimum with what CI actually runs.

## For consumers

**Breaking**: the minimum supported Node runtime is now 24.0.0
(previously 22.0.0). Consumers on Node 22 may continue using
0.5.x or upgrade after migrating to Node 24.

**Breaking**: the npm package name changed from
`@backshopdev/opencode-roundhouse` to `@backshopdev/roundhouse`,
and the CLI binary changed from `opencode-roundhouse` to
`roundhouse`. Migration: update install commands and CLI
invocations to the new names.

**Breaking**: the dedicated `investigator` agent is removed.
Custom configurations that explicitly load or assign the
`investigator` agent must be updated to load the `investigation`
skill instead (the skill is available to orchestrator,
document-author, and implementor allowlists).

No other consumer-facing changes. Prose-authoring workflows
using `document-author` continue to work without modification.

## For contributors

The four-agent topology (orchestrator, document-author,
implementor, reviewer) is now complete. The harness skill
documents progressive specialization and skill architecture
patterns; the `implementor` agent and `investigation` skill
are the first consumers of that contract. New skills should
follow the same layering discipline — see
`docs/decisions/DEC-20260905-01.md` and the harness skill's
"Progressive specialization" section.

Open KTLO items worth tracking:
- KTLO-20260905-01: review the document-author vs. implementor
  skill allowlists post-launch; the two agents currently mirror
  each other, which is a starting position, not a permanent one.
- KTLO-20260902-01: completion-packet footer enhancements
  (domain-skills, review-verdicts) — open since 0.5.x, still
  relevant for 0.7.0+.
- Pre-existing 12 docs-check index-discipline failures in
  `docs/` and `ktlo/` were not addressed in this release;
  deferred pending investigation of a possible validator bug.
- Plan a Node 26 LTS bump ~6 months before Node 24 EOL
  (April 2028).
