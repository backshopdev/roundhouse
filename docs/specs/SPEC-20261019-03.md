# SPEC-20261019-03: Phase 5+6 atomic cutover

## Purpose

Define the combined Phase 5+6 changeset (DEC-20261017-03): the atomic
source-tree cutover that moves every tracked `src/` path into the package
trees per the committed fixture's ownership annotations, instantiates the
Core template from `src/opencode.json`, joins the five taxonomy-resolved
packages to the workspace, swaps the legacy tooling for composer-backed
wrappers, and leaves the repository in the post-cutover state — `src/` empty
of tracked paths, the packages the single authoritative source, the root
harness composed via the self-hosting flow. The tooling swap preserves the
managed-overwrite and seed-create-if-missing semantics with no broken-tooling
window. This specification consumes the committed composer behavior
(SPEC-20261019-02); it does not redefine it. It describes proposed behavior
subject to human and review signoff; `Active` is its document lifecycle
status, not evidence that the cutover has been performed.

## Scope

### Included

- **The move map.** The fixture-driven disposition of all 89 tracked `src/`
  entries in the committed fixture: 61 managed entries (57 carrying
  package-name owners, 4 carrying TODO rationales) and 28 seed entries
  (Public contracts, The move map).
- **The four TODO resolutions.** The security-privacy and gherkin-testability
  splits, the image-media-delivery retirement, and the planning-structure
  rename — each per its annotation's rationale (Public contracts, The four
  TODO resolutions).
- **The taxonomy rename realization.** DEC-20261017-02's rename-wave
  commitment — the renames, splits, and folds of the skill taxonomy — lands
  in this changeset: content moves once, at its final taxonomy ID, with no
  double-touching (Public contracts, The move map).
- **The five taxonomy-resolved packages.** `software-security`,
  `software-privacy`, `lang-gherkin`, `software-testing`, and the
  backshopdev-planning package join the workspace with their content
  (Public contracts, The new packages).
- **The template instantiation.** `packages/roundhouse-core/opencode-template.json`
  derived from `src/opencode.json` by the reduction and normalization rules
  (Public contracts, The template derivation).
- **The tooling swap.** `scripts/sync-roundhouse.js` and
  `package/deploy-roundhouse.js` (with `package/roundhouse.js`) become thin
  adapters over the composer library, preserving the observable CLI and API
  surfaces (Public contracts, The wrapper contract).
- **The post-cutover state.** The root harness composed via the self-hosting
  flow; the fixture consequence (Public contracts, The post-cutover state).

## Terminology

| Term | Meaning |
| --- | --- |
| Move map | The fixture-driven disposition of every tracked `src/` entry: managed entries to their annotated owner's `managed/` tree at the taxonomy-ruled destination path (skill IDs take their DEC-20261017-02 taxonomy IDs; non-skill managed paths mirror their `.opencode/`-relative paths); seed entries to `packages/roundhouse-core/seed/` at the consumer-root-relative path; `src/opencode.json` to the template derivation. |
| Mirrored path | The destination path under a package's `managed/` tree equal to the source path's `.opencode/`-relative remainder (`src/.opencode/X` → `<owner>/managed/X`) — the rule for non-skill managed content. |
| TODO resolution | The disposition of a TODO-annotated managed path per its annotation's rationale: split, retire, or rename. |
| Rename | A skill-ID change at move time: the source's content lands byte-preserved at the destination ID's path; the source ID retires. The destination IDs are DEC-20261017-02's taxonomy entries. |
| Split | A source skill directory whose content divides into two new skill directories; the source path is deleted. |
| Fold | Two source skill directories whose content merges into one destination skill directory; both source paths are deleted. |
| Template instantiation | The derivation of `packages/roundhouse-core/opencode-template.json` from `src/opencode.json` by the reduction and normalization rules; the source's destiny is the composed-artifact class its CLI annotation names. |
| Wrapper | A thin adapter (`scripts/sync-roundhouse.js`, `package/deploy-roundhouse.js`, `package/roundhouse.js`) whose observable surface is preserved while the composer library becomes the engine. |
| Self-hosting flow | The root repository acting as its own consumer: the sync wrapper's `--mode sync` runs the composer's init (when no root manifest exists) or compose, with the workspace members as the discovered set. |
| Husk | The empty `src/` directory remaining after the cutover, deleted in Phase 8. |
| Pre-cutover snapshot | The repository state immediately before the cutover changeset — Phase 7's comparison baseline. |

## Constraints

- **One changeset, no broken window.** The content moves and the tooling swap
  land in one commit (DEC-20261017-03's granularity); after the changeset
  every suite is green and both npm scripts function.
- **The naming resolution.** The backshopdev-planning package's npm name is
  ruled (2026-10-19): `@backshop/roundhouse-backshopdev-planning` — the org
  as a family token inside the `roundhouse-*` name; future `backshopdev-*`
  packages follow `@backshop/roundhouse-backshopdev-<subject>`. The
  planning-structure move's precondition is satisfied.
- **Fail-closed via the composer.** Every composition step runs the committed
  composer's validation before any write; a validation failure exits 1 and
  writes nothing (SPEC-20261019-02's constraint, inherited).
- **Byte-preserving moves.** Managed and seed entries move with content
  unchanged — byte preservation against the fixture's recorded hashes — at
  the destination paths the move map rules: non-skill managed paths mirror
  their `.opencode/`-relative paths; skill paths take their taxonomy IDs
  (the rename map). The transformation dispositions (five splits, two folds,
  one retirement, and one augmentation — the docs-general dictum content)
  are the only content transformations.
- **The annotation loud-drop.** The post-cutover fixture regeneration drops
  all 61 managed annotations loudly (the generator's stale-annotation flow:
  written without them, exit 1, review-and-rerun); the annotations' purpose
  is realized by the move, and the committed post-cutover fixture carries no
  `src/` entries and no annotations.
- **Root content discipline.** The cutover changes no consumer-owned root
  file's content (the root seeds are untouched); the root's composed
  artifacts (`opencode.json`, `.roundhouse/manifest.json`) are the rendered
  outputs the composer owns.
- **Canonical serialization.** Every created or regenerated JSON artifact
  (the template, the manifests, the composed `opencode.json`) follows the
  committed canonical serialization (UTF-8 without BOM, LF, two-space
  indentation, pinned member order, single trailing newline).
- **Node 24, built-ins only.** The wrappers add no dependencies; the
  composer's zero-dependency posture holds.

## Quality attributes

- **Atomicity:** One changeset carries the moves, the template, the new
  packages, the wrappers, and the regenerated fixture; no intermediate state
  is committed where content has moved but tooling cannot compose it.
- **Determinism:** The template derivation from the same source is
  byte-identical; the composed root `opencode.json` from the same discovered
  set is byte-identical; both assertable by test.
- **Integrity:** Every byte-preserving move's bytes equal its source's bytes
  (the fixture's SHA-256 values verify the pre-move state; the moves preserve
  them); the nine transformation dispositions (five splits, two folds, one
  retirement, and one augmentation — the docs-general dictum content) are
  the only content transformations.
- **Reliability:** Exit codes 0/1/2 across the wrapper surfaces, mirroring
  the composer precedent; every removal, creation, and
  rejection listed on stderr; zero silent mutations.

### The template derivation

`packages/roundhouse-core/opencode-template.json` is derived from
`src/opencode.json` as committed at cutover time:

1. **Verbatim members:** `$schema`, `default_agent`, the four built-in agent
   entries (`build`, `plan`, `general`, `explore` — each `{ "disable": true }`),
   each Core agent's `mode` and tuning member (`steps` for the orchestrator,
   `temperature` for each subagent), and every `permission` member other than
   `skill` and `bash` (the `read`, `glob`, `grep`, `list`, `edit`, `task`,
   `question`, `webfetch`, `websearch` shapes).
2. **Skill-map reduction:** each Core agent's `permission.skill` map becomes
   exactly `{ "*": "deny" }` — the hand allow-lists are dropped; the
   composer's computed uniform unions replace them at render time.
3. **Bash normalization:** the reviewer's bare `"bash": "deny"` string
   becomes the map `{ "*": "deny" }` (the Phase 3 invariant's Phase 5
   consequence); the document-author and implementor bash maps carry over
   verbatim; the orchestrator's absent bash key stays absent (the rendered
   map contains only the union block).
4. **Shape:** member order preserved from the source; canonical
   serialization; the result passes the committed Phase 3 template-validation
   contract (the six invariants) — the derivation rules are exactly the
   inverse of the validation rules.
5. **Determinism:** deriving twice from the same source yields
   byte-identical output.

### The wrapper contract

The three legacy tooling files become thin adapters replacing the legacy
implementations in place — the pre-wrapper implementations retire to git
history (ruled 2026-10-19; DEC-20261017-03's `tooling/` relocation language
is superseded by this ruling, flagged for the DR-03 amendment wave). No
`tooling/` directory is created. The composer library is the engine. The
observable surfaces are preserved so the npm scripts and the test suites
keep working:

- **`scripts/sync-roundhouse.js`** — the CLI surface preserved:
  `--mode sync` and `--mode verify`, strictly parsed (any other invocation is
  a usage error, exit 2, usage text on stderr), exit codes 0/1/2.
  `--mode sync` → the self-hosting composition: the composer's init when the
  root carries no `.roundhouse/manifest.json`, compose otherwise, with the
  workspace members as the discovered set — managed artifacts updated,
  stale managed files removed by recorded ownership, `opencode.json`
  regenerated, newly applicable seeds created only when missing, the
  manifest refreshed. `--mode verify` → the composer's verify against the
  root, read-only.
- **`package/deploy-roundhouse.js`** — the exported API preserved
  (`ROOT_ONLY`, `collectRelativePaths`, `copyMissing`, `deploy`, `init`,
  `update`) as adapters over the composer's safe-fs primitives and
  materialization; `package/roundhouse.js`'s bin (`init` / `update`, with
  `--dry-run`) preserved and dispatched to the same composer flow. The
  effective content source is the local workspace package set; the
  src/-based parameters become inert compatibility surface where they cannot
  be honored post-cutover.
- **The preserved semantic pair:** managed-overwrite (managed artifacts are
  overwritten on every sync/update) and seed-create-if-missing (seed
  instances are created only when absent and never overwritten). The
  rejection contracts — managed-root type conflicts, junction/symlink
  rejection, path-escape rejection — hold unchanged through the composer's
  safe-fs layer. The stale-removal detail follows the composer's
  recorded-ownership rule (never-recorded files are never removed); the
  legacy blanket removal retires with the source-tree model, and the suites
  adapt where that detail differs.
- **The suites adapt minimally.** `scripts/test-sync.js` and the lifecycle
  block of `scripts/test-package.js` keep their behavioral contracts
  (overwrite, seed preservation, dry-run non-mutation, rejections,
  self-hosting) with the content source relabeled from `src/` to the
  packages; assertions whose expected bytes change (`opencode.json`'s
  composed content) or whose stale detail differs (recorded ownership)
  adapt to the new expected values, with the composer's own suite carrying
  the owned-stale-removal coverage.
