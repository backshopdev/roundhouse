# Literature Note

## Expert stance

Apply rigorous research-synthesis judgment. Treat a literature note as a compact
evidence interface: a future reader should know what was accessed, what the
source actually supports, what the note author inferred, and how strongly a
project principle follows. This expertise composes with the caller's role and
does not introduce a separate persona.

## Domain model

- **Primary source:** the work being represented; **secondary source:** another
  author's account of it. Do not silently transfer claims between them.
- **Provenance:** author/publisher, title, version or date, stable location,
  retrieval date, and the exact representation inspected.
- **Retrieval status:** full, partial, abstract/snippet only, inaccessible, or
  local capture. Availability is not evidence of having read the source.
- **Source claim:** attributable statement or finding. **Inference:** the note
  author's synthesis. **Implication:** a proposed project consequence.
- **Principle mapping:** the evidential link from source material to a reusable
  project principle; its strength depends on directness and scope fit.

## Evidence judgment

Ask what representation was actually inspected, whether wording preserves the
source's scope and uncertainty, and whether the note distinguishes quotation,
paraphrase, inference, and recommendation. Check whether a cited passage proves
the mapped principle or merely resembles it.

| Evidence state | Permitted use | Required qualification |
| --- | --- | --- |
| Full primary source | Summarize supported claims in context | Note material limitations |
| Partial primary source | Use only inspected portions | Identify missing scope |
| Abstract or snippet | Establish only what it explicitly says | Label limited access |
| Secondary account | Attribute the account to that source | Do not imply primary verification |
| Local capture | Use if identity and capture provenance are clear | Record capture path/date and origin |
| Inaccessible | Record discovery and access failure | Make no content claim from it |

A principle mapping is **strong** when direct source support and project scope
align, **qualified** when interpretation or transfer is needed, and
**unsupported** when the source does not establish the stated principle.
Contrary evidence, inaccessible context, and source limitations lower strength;
they are not details to omit for concision.

## Preferred and discouraged patterns

Prefer precise attribution, claim-level location cues, short paraphrases,
explicit uncertainty, stable links, and concise synthesis designed for reuse.
Use quotations only when exact language matters.

Discourage polished summaries detached from provenance, citation laundering
through secondary sources, unsupported author attribution, extrapolating from a
title or snippet, presenting interpretation as fact, and bloating notes with a
source's full narrative rather than decision-relevant evidence.

Warning signs include absent retrieval status, metadata copied without
verification, claims broader than the cited passage, recommendations phrased as
the source author's position, broken local captures, and principles linked to a
note that never states their evidential basis.

## Authoring guidance

1. Record identity, location, retrieval date/status, representation inspected,
   and access limitations before synthesis.
2. Organize compactly into source claims, interpretation, project implications,
   and principle mappings. Preserve the source's terminology where precision
   matters; define any project translation.
3. Give high-value claims enough page, section, heading, timestamp, or quoted
   context to permit verification. Never fabricate precision.
4. Mark conflicts and uncertainty rather than resolving them without evidence.
5. Follow repository frontmatter, index, and relative-link rules; add only links
   that the repository can resolve.

## Multi-source synthesis workflow

When a task involves multiple sources:

1. **Intake**: Receive handoff packet or research brief identifying the sources.
2. **Analyze**: Create a literature note for each source, marking retrieval
   status and access limitations before synthesis.
3. **Synthesize**: Identify patterns across sources and extract common
   principles. Note convergence when multiple sources support the same pattern.
4. **Update principles**: Refine or create guiding principles based on
   synthesized evidence.
5. **Update dependent docs**: Ensure documents that reference changed principles
   are updated when principles change.

## Handoff packet guidance

Handoff packets may reference multiple sources with varying retrieval status.

- Mark each source's retrieval status honestly (abstract/snippet only, partial,
  full text, inaccessible).
- Distinguish source claims from inferences and from implications.
- When multiple sources support the same pattern, note the convergence and the
  strength it adds to the principle mapping.
- When sources conflict, document the disagreement explicitly and assess which
  source is more applicable to the project scope. Do not silently resolve
  conflicts by favoring one source without justification.

## Review guidance and escalation

Sample the most consequential claims against the inspected source or local
capture. Verify metadata, attribution, retrieval language, citation health,
fact/inference separation, and each principle mapping's strength. Require the
note itself to disclose material access limits.

Escalate when the primary source is unavailable but a strong attribution is
claimed, provenance cannot identify the inspected artifact, a recommendation
depends on disputed evidence, or a principle materially exceeds source support.
Report the exact claim and evidence gap; do not merely request "more citations."
