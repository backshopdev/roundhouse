## Description

The repo's `index.md` entry formats are enforced mechanically (docs-check
validates link resolution, statuses, dates, and index structure) but are
codified nowhere an agent or human can read while authoring a new index or
row. The intended canonical shapes — the populated table for durable
document collections (columns `Title | Description | Status | Date` in that
order), the em-dash bullet list for items carrying inline metadata
(`[template]`/`[project]` tags, retrieval status), and the section-navigation
bullet list for top-level sub-area indexes — exist in practice across the
repo's indexes, but no durable document states them. The old plan
(PLAN-20260904-01, superseded) aimed at this codification and never landed
it; its target skill (`repository-documentation`) was dissolved in the
package-family migration.

## Trigger

The 2026-10-21 docs-hygiene session (PLAN-20261021-03): while archiving
plans and specs and editing index rows, the implementor had to infer the row
format from neighboring rows and the docs-check source rather than from any
codified rule — the same gap PLAN-20260904-01 (2026-09-04) was created to
close and never did.

## Evidence

- PLAN-20260904-01's state: Status "Ready" since creation, never
  implemented; archived Superseded by PLAN-20261021-03 WP-02 T-05.
- The three index shapes exist in the repo (e.g., `docs/specs/index.md`'s

- docs-check validates the outcomes (links, statuses, dates) but carries no
  human-readable statement of the intended row formats.

## Why this matters now

Every author of a new index or row re-derives the format by imitation or by
reading docs-check's source; the imitation can silently diverge (an index
copied from the wrong exemplar) and the divergence surfaces only at
docs-check time or not at all. The repo's index discipline is otherwise
machine-checked, so the gap is discoverability, not correctness — but
discoverability is what keeps new consumer repos (the seed copies) conformant
without a maintainer in the loop.

## Resolution criteria

Done when the docs-general skill (the installed documentation-authoring
skill) carries the codification and a reader with no prior context can
produce a conformant index from it: the three patterns (populated table,
em-dash bullet list, section navigation) with their selection rule
(directory role), the populated table's canonical column order
(`Title | Description | Status | Date`), the bullet list's canonical field
shape, and the empty-placeholder form — verified by authoring or editing one
index row using only the skill's text and getting docs-check green on the
first attempt.

## Impact

- Severity: Low
- Affected systems: the docs-general skill (the codification's home), every

3. Close the item per the house KTLO closure pattern.
