# KTLO-20261009-02: Skill taxonomy (when the skill set stabilizes, define a proper taxonomy)

Last modified: 2026-10-09
Status: Active

## Description

<!-- Describe the operational maintenance task, known issue, or recurring
work. -->

The `README`'s "five categories" claim was dropped because the actual skill
set did not fit cleanly into named buckets. When the skill set stabilizes,
define a proper taxonomy of named categories and document which skills
belong to each. Skills may fit in more than one category; allow overlap
rather than forcing a single assignment.

## Impact

<!-- What happens if this item is not addressed? -->

- Severity: Low
- Affected systems: Repository `README.md`; any documentation or tooling
  that references skill categories.

Documentation accuracy issue, not a behavioral issue. Without a
documented taxonomy, future authors may re-introduce ad hoc groupings
that do not match the actual skill set, repeating the inaccuracy that was
recently removed.

## Recurrence

<!-- How often does this work need to be done? -->

- Frequency: As needed
- Estimated effort: A short design pass plus a `README.md` update once the
  skill set has settled.

## Procedure

<!-- Step-by-step instructions for performing this work. -->

1. Wait until the skill set has been stable (no additions, removals, or
   retirements) for a reasonable period.
2. Survey the current skills and group them by purpose, audience, and
   trigger conditions.
3. Draft a named-category taxonomy that covers all current skills and
   allows a skill to appear in more than one category.
4. Update the `README.md` to reference the taxonomy in place of any
   prior "five categories" claim.
5. Cross-check the taxonomy against the orchestrator's and
   document-author's skill allowlists to confirm the categories reflect
   actual scope of work.
