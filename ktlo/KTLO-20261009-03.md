# KTLO-20261009-03: README accuracy: "seven skills across three categories" claim

Last modified: 2026-10-17
Status: Resolved

## Description

<!-- Describe the operational maintenance task, known issue, or recurring
work. -->

`README.md` line 117 contained a "seven skills across three categories"
claim that used the same enumeration pattern that was problematic on
an earlier line (the dropped "five categories" claim). At item creation
the orchestrator's skill allowlist contained 4 skills, not 7. This was a
pre-existing potential accuracy concern to be reconciled when the
surrounding documentation was updated.

## Resolution

Resolved without a README edit under this item: by the time of closure,
`README.md` line 117 had already been reworded to a self-referential
statement ("enumerated in the skill allowlist") with no count, removing
the stale enumeration pattern. The count premise is also superseded: on
2026-10-17 the orchestrator skill allowlist was expanded from 4 to 21
allows in `src/opencode.json`, so any count-based wording would go stale
on every allowlist change; the self-referential wording avoids that
failure mode permanently.

## Impact

<!-- What happens if this item is not addressed? -->

- Severity: Low
- Affected systems: `README.md`; reader expectations about the size and
  shape of the skill set.

Documentation accuracy issue, not a behavioral issue. Readers may form
incorrect expectations about the skill set, and any future agent that
parses the `README` for facts about the project would receive stale
counts.

## Recurrence

<!-- How often does this work need to be done? -->

- Frequency: As needed
- Estimated effort: A small `README.md` edit once the canonical skill
  count and grouping are confirmed.

## Procedure

<!-- Step-by-step instructions for performing this work. -->

1. Confirm the current skill count by enumerating the skills listed in
   the orchestrator's and document-author's allowlists (and any other
   authoritative source).
2. Decide on the replacement wording: either an accurate count, a
   self-referential statement ("see the skill allowlist"), or removal of
   the count in favor of a stable description.
3. Update `README.md` line 117 to reflect the decision.
4. Run `node .opencode/docs-check.js` and `npx --yes
   markdownlint-cli2@0.23.2` to confirm no documentation regressions.
