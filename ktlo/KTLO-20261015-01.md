# KTLO-20261015-01: Assess deferred Git inspection allowances

Last modified: 2026-10-15
Status: Active

## Description

Track deferred proposals for narrowly scoped document-author Git inspections.
This project item records operational context and candidates for later human
approval; it does not authorize or implement any deferred allowance.

During prior approved commit preparation, `git ls-files --stage --` followed
by four paths was attempted to record staged blob hashes and file modes. The
command was rejected by the broad Git denial because there was no `ls-files`
exception. The same evidence was then obtained through the permitted
`git diff --cached --raw --no-abbrev` command. An earlier, separate staging
compound command was also denied, but its cause remains unresolved; that
denial is not evidence of the confirmed `ls-files` allowlist gap.

The approved narrow correction adds only `git ls-files` and `git ls-files *`
to document-author's Bash allowlist in [the source configuration](../src/opencode.json),
then deploys it through the normal sync. This useful inspection allowance was
chosen despite the available diff alternative; it does not change other roles,
commit/push/destructive protections, or human approval gates.

Deferred candidates, none enabled or automatically authorized by this item:

- Selected `git rev-parse` forms, such as `--verify` for hashes.
- `git merge-base --is-ancestor` for local ancestry and assessing currentness
  against local refs only; this does not establish remote freshness.
- `git check-ignore` for diagnosing ignored scratch paths.
- Lower-priority `git show` inspection forms; existing diff/log commands often
  provide sufficient evidence.

Avoid broad `git branch *`, `git remote *`, or `git config *` allowances. Consider
specific read forms only when a real need is demonstrated. Evaluate option,
helper-execution, and sensitive-disclosure risks rather than assuming all
read-only inspection is harmless.

## Impact

- Severity: Low
- Affected systems: document-author Git inspection permissions and commit
  preparation evidence collection.

Unassessed gaps can interrupt routine evidence collection or require alternate
commands. Overbroad fixes could authorize writes, helper execution, or disclosure
of sensitive configuration or remote details.

## Recurrence

- Frequency: As needed, when an actual inspection need is blocked.
- Estimated effort: Bounded assessment per demonstrated command form; scope and
  verification require a later approved plan.

## Procedure

1. Capture the concrete inspection need, exact rejected command, relevant
   permission evidence, and any already permitted alternative. Keep unresolved
   compound-command denials separate from confirmed allowlist gaps.
2. Assess only needed command forms and their options, helper behavior, and
   disclosure risks. Preserve role boundaries and existing Git protections;
   do not substitute broad branch/remote/config allowances.
3. Propose the smallest justified change and verification scope through the
   orchestrator for human approval. These candidates remain deferred proposals
   until that approval; this procedure grants no implementation authority.
