## Description

The repo's dependency surface currently consists of GitHub Actions
(SHAs pinned in `.github/workflows/publish.yml`) and one `npx`
invocation (`markdownlint-cli2@0.23.2`). As of v0.6.0 we have zero
runtime or dev dependencies in `package.json`. The moment we add any
runtime, dev, or peer dependency, the question of how to pin becomes
load-bearing.

This KTLO establishes the policy: **pin all dependency versions
exactly**, and treat every dependency update as a deliberate,
conscious act — not an automatic or incidental one. The principle
applies equally to:
- Future `package.json` dependencies (exact pins, no caret/tilde ranges)
- Future `npx` invocations (exact spec, not bare package name)
- Any other package-fetching tool invocation added later

A complementary principle: any version update is a pause-and-escalate
event. Even if a dependency publish is benign-looking, the update
must be reviewed and explicitly approved before landing — to limit
the impact of a potential supply-chain compromise and to make every
version bump a conscious choice.

The principle does not prevent supply-chain attacks; it makes them
slower, smaller, and more visible. If a compromised version lands,
the deliberate-update workflow means a human noticed it before it
shipped, and the git history shows exactly when and why.

## Benefits

- Compromised dependency update requires passing a human review gate.
- Version bumps are visible in PRs as distinct, intentional changes.
- `git log` and `git blame` show the rationale for every dependency
  update.
- No silent drift from a pinned version.
- Compatibility with `npm ci` (which uses the lockfile exactly and
  fails on lockfile drift).

## Challenges

- New contributors may instinctively reach for `^` or `~` ranges;
  will need to be caught at PR review.
- Some tooling (e.g., Dependabot, `npm update`) defaults to caret
  ranges; if we adopt those, we'll need configuration overrides.
- Future Node.js skill (if created) would need to encode this
  policy for agent-driven dependency decisions; until that exists,
  this KTLO is the only place the principle is written down.
- Pause-and-escalate workflow depends on a human being present and
  paying attention; a missed PR review is the failure mode.

## Exit criteria

- Policy is encoded in a durable location (DEC or skill frontmatter),
  not just this KTLO.
- A release-prep or dependency-update checklist exists that names
  "pin exact version" as a required step.
- If a Node.js skill is created, this principle is one of its
  primary guidance items.
